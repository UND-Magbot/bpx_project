 BPX 4족로봇 ROS 2 개발 착수 (자료 분석 · 미니PC 제어 계층 선구축)

1. 자료 분석 (완료)
  제조사 GitHub(mirrormerobotics) 저장소 8개와 사용자·조립 매뉴얼 2종을 전부 읽었다.
  매뉴얼에는 치수·컴퓨트·SDK 정보가 없어서, 스펙은 URDF와 SDK 헤더에서 뽑았다.
  BPX는 12자유도이고 무게는 15.2 kg이다. BPX-Pro는 17.6 kg이고 무릎 토크가 50 Nm이다. 최대 탑재 하중은 5 kg이다.
  SDK는 ROS·DDS가 아니라 자체 TCP/UDP 프로토콜을 쓴다. 코어는 소스 없이 바이너리로만 배포되고, 인증이 없다.
  공개 ROS 연동(Robonix)은 읽기 전용이고, 강화학습 저장소는 실기 배포를 범위에서 빼 두었다.
  → ROS 2 드라이버는 SDK를 감싸서 직접 만들어야 한다.

2. 구조 결정
  Zishen 때와 같이 로봇에 올린 미니PC가 전부 제어한다. 미니PC는 새 PC를 쓴다.
  보행은 로봇 펌웨어가 처리하고 상위에서는 /cmd_vel만 주는 방식이라, Zishen 구조를 그대로 옮길 수 있다.
  TF 트리(map → odom → base_link)와 odom 토픽명(/odom/mc_odom)은 Zishen과 맞췄다.
  단, 새 PC에는 genisom 스택이 없다. Zishen Nav2는 벤더 포크(navigo_)라 이식이 안 되므로, Nav2는 표준 패키지로 새로 구성한다.

3. ROS 2 제어 계층 구축 (로봇·PC 없이 선작업)
  - SDK 브리지 노드: Zishen cmd_vel_bridge를 BPX SDK로 이식했다.
    - /cmd_vel → 속도 명령
    - 다리 odom → /odom/mc_odom + TF
    - 관절·IMU·배터리·상태 발행
    - 서기·앉기·힘풀기 서비스
  - 안전 쪽 기본값: 기본이 읽기 전용이고, 자동으로 일어서지 않는다. Zishen은 켜자마자 일어섰는데 이를 바꿨다.
    - /cmd_vel이 0.5초 끊기면 정지하고, 속도는 제한값으로 자른다.
    - 연결이 끊겼다 붙으면 서기 절차부터 다시 밟는다. SDK가 재연결 후 명령을 재전송하지 않기 때문이다.
  - Fake 백엔드: 로봇 없이 서기·주행·앉기 흐름을 흉내 낸다.
  - 로봇 모델과 동작 스크립트: URDF에 ROS 표준 루트(base_link)를 추가했다. 단발 동작 스크립트(check/stand/sit/damping/zero)를 만들었다.
  - 미니PC 설치 스크립트: ROS 2 Humble, SDK, 방화벽(UDP 9873), 빌드까지 한 번에 한다. SDK 설치 파일은 저장소에 같이 넣어 오프라인 설치가 된다.
