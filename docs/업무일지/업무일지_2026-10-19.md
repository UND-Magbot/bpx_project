 BPX 4족로봇 첫 실기 연결 · 로봇 관리자 웹 구축 · 첫 동작(일어서기/앉기) 성공

1. 로봇 첫 실기 연결 (완료)
  미니PC와 로봇을 랜선으로 연결했다. 미리 잡아 둔 설정 그대로 바로 연결되었다.
  로봇을 움직이지 않는 읽기 전용으로 먼저 붙여서, 문서에 없던 데이터 단위를 실측으로 확인했다.
    - 자세 센서(IMU) 가속도는 표준 단위(m/s²)이고, 센서가 몸체와 수평으로 장착되어 있다.
    - 엎드린 자세의 관절 각도가 로봇 모델(URDF)과 부호·크기가 일치한다.
    - 모터 온도는 ℃, 배터리 전류는 A 단위이고 충전 중이면 양수다.
  로봇 펌웨어는 1.0.14로, 제조사가 동작 검증에 쓴 1.0.15보다 한 단계 낮다.
  이 때문에 일부 정보(시리얼 번호, 조종 주체)는 받아오지 못한다.

2. 로봇 관리자 웹 구축 (완료)
  AMR 개발 때처럼 브라우저로 로봇을 관리하는 웹을 만들었다. 미니PC를 켜면 자동으로 실행된다.
    - 상태 화면: 연결, 동작 상태, 배터리, 모터 온도, 속도, 위치, 작업 기록
    - 동작 버튼: 일어서기, 앉기, 힘 풀기, 비상 정지, 관절 영점
    - 원격 조종: 화면 조이스틱 또는 키보드
    - 지도·위치: 지도 위에 4족 로봇 모양으로 위치와 방향을 표시하고, 목표점을 찍어 자율주행을 보낼 수 있다(라이다 연결 후 사용).
  안전을 위해 다음과 같이 만들었다.
    - 켜면 항상 읽기 전용이다. "조종 모드"를 켜야만 로봇에 명령이 전달된다.
    - 조이스틱은 누르는 동안만 명령이 나간다. 손을 떼거나, 통신이 끊기거나, 창을 닫으면 즉시 정지한다.
    - 속도 상한을 이중으로 걸었다.
  → 인증이 없어 같은 망의 누구나 조종할 수 있다. 사내 시험망에서만 쓴다.

3. 첫 동작 시험 (완료)
  웹에서 일어서기를 눌렀는데 로봇이 반응하지 않는 문제가 있었다.
  패킷을 직접 캡처해 확인해 보니, 일어서기 명령은 정상적으로 로봇까지 도착하고 있었다.
  원인은 충전기 연결이었다. 충전 중에는 로봇이 스스로 동작을 잠가서 명령을 무시한다.
  충전기를 뺀 뒤 웹에서 일어서기와 앉기가 정상으로 동작했다. 실제 로봇을 처음 움직인 것이다.
  → 제조사 SDK의 "충전기 연결" 정보는 이 펌웨어에서 충전 중에도 "연결 안 됨"으로 나와 원인 파악이 늦어졌다.
     대신 배터리 전류로 충전 여부를 판단하도록 바꿨다.
     충전 중에 일어서기를 누르면 바로 "충전기를 빼세요"라고 알리고, 웹 화면에도 "충전 중 · 동작 불가"를 표시한다.

4. 다음 할 일
  - 저속 주행 시험: 조이스틱으로 전진·회전·옆걸음, 손을 떼면 멈추는지 확인
  - 주행 중 위치 방향(앞 = +x, 왼쪽 = +y)과 센서 축 방향 확인
  - 펌웨어 업데이트 검토 (1.0.14 → 1.0.15 이상): 조종 주체 등 누락 정보 확보
  - 라이다 도착 시: 지도 만들기 → 위치추정 → 웹 지도에서 목표점 자율주행
  - 제조사 문의: 배터리 출력 포트 허용 전류, 충전기 연결 정보 오류, 앱/리모컨과 프로그램 명령의 우선순위
