 BPX 4족로봇 관리자 웹 확장 (진단 · 시스템 · 매핑 · 지도 관리)

1. 진단 · 시스템 화면 추가 (완료)
  - 진단 화면: 관절 12개의 각도·속도, 모터와 드라이버 온도(60℃ 주의, 70℃ 위험 색 표시), 자세 센서 값,
    펌웨어 버전, 배터리·전류·온도의 30분 추이 그래프를 볼 수 있다.
  - 시스템 화면: 미니PC의 CPU·메모리·디스크·온도, 로봇/라이다/WiFi 포트 연결 상태, 실행 중인 프로그램 목록을 보고,
    로봇 연결 프로그램을 재시작할 수 있다.
  - 보행 모드(걷기/달리기) 전환을 추가했다. 서 있을 때만 바꿀 수 있고, 속도 상한은 그대로 유지된다.
  - 게임패드 조종도 만들었으나, 당장 필요 없다는 판단으로 화면에서 뺐다. 코드는 기록에 남겨 두어 필요하면 되살릴 수 있다.

2. 매핑 화면 추가 (완료)
  웹에서 지도 이름을 넣고 시작하면 로봇이 이동하는 동안 지도가 실시간으로 그려진다.
  바닥과 천장은 빼고 벽·장애물 윤곽만 보여 주어, 지도가 제대로 만들어지는지 현장에서 바로 확인할 수 있다.
  "저장하고 종료"를 누르면 지도 기울기 보정과 자율주행용 2D 지도 생성까지 자동으로 끝난다 (약 2초).

3. 지도 관리 화면 추가 (완료)
  - 지도 목록과 미리보기, 활성 지도 지정, 이름 변경, 다시 처리, 삭제를 할 수 있다. 사용 중인 지도는 지워지지 않게 막았다.
  - 활성 지도로 위치추정(필요하면 자율주행까지)을 웹에서 시작/정지한다.
  - 로봇이 매핑 시작점이 아닌 곳에 있을 때를 위해, 지도에서 로봇 위치를 찍어 주는 "초기 위치" 기능을 넣었다.

4. 시험 (완료)
  라이다가 아직 없어서 공개 라이다 데이터로 전체 흐름을 시험했다.
  매핑 → 저장 → 자동 처리 → 활성 지정 → 위치추정 → 이름 변경·삭제까지 15개 항목, 기존 조종 기능 10개 항목을 모두 통과했다.
  시험 중 두 가지 문제를 찾아 고쳤다.
    - 시험 데이터로 위치추정을 돌리면, 이미 돌고 있는 로봇 연결 프로그램과 위치 정보가 충돌해 위치가 움직이지 않았다.
      → 시험 모드에서는 위치 정보 이름을 분리했다.
    - 넓은 실외 지도는 2D 지도가 약 80MB로 커서 웹으로 보낼 수 없었다.
      → 서버에서 줄여서 보내되, 얇은 벽이 사라지지 않도록 장애물을 우선해 줄이게 했다.

5. 지도 방식 검토 (3D vs 2D)
  3D 지도를 기준으로 만들고, 자율주행 경로 계획에 쓰는 2D 지도는 3D에서 잘라 쓰는 방식으로 정했다 (현재 구조).
    - 위치추정은 3D 지도를 쓴다. 4족은 걸을 때 몸이 흔들려서, 2D로 하면 위치가 쉽게 흐트러진다.
    - 2D 지도는 기준(장애물 높이, 해상도)을 바꿔 언제든 다시 만들 수 있다.
  → 라이다 장착 방향이 중요하다. Mid-360S는 아래쪽을 7°밖에 보지 못해서, 수평으로 달면 로봇 앞 약 3m 안의 낮은 장애물을 못 본다.
     거꾸로 달거나 앞으로 20~30° 숙여 다는 것을 권장한다.

6. 다음 할 일
  - 라이다 장착 방향과 높이 결정 → 라이다 위치값과 2D 지도 기준값 반영
  - 라이다 도착 시: 실제 장소 매핑 → 위치추정 → 웹에서 목표점 자율주행 시험
  - 로봇 저속 주행 시험 (조이스틱, 방향 확인)
  - 펌웨어 업데이트 검토, 제조사 문의(배터리 출력 포트 전류, 충전 정보 오류, 명령 우선순위)
