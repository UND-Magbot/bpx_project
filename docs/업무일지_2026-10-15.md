 BPX 4족로봇 미니PC 초기 세팅 · 로봇 없이 제어 계층 검증 · 라이다 결정

1. 미니PC 초기 세팅 (완료)
  새 미니PC(MSI PRO Cubi Z AI 8M)에 Ubuntu 22.04를 설치하고 SSH를 설정했다.
  설치 스크립트로 ROS 2 Humble, BPX SDK 1.0.9, 워크스페이스 빌드까지 끝냈다.
  설치 스크립트가 빌드 단계에서 멈추는 오류가 있어 고쳤다. 다음 PC부터는 스크립트 하나로 끝난다.
  유선 랜포트 두 개에 고정 IP를 미리 잡아 두었다. 랜선만 꽂으면 바로 연결된다.
    - eno1 → 로봇용 (10.21.20.10)
    - enp4s0 → 라이다용 (192.168.1.50)
  프로젝트 폴더를 git으로 관리하기 시작했다.

2. 로봇 없이 제어 계층 검증 (완료)
  - 가짜 로봇(fake)으로 전체 흐름 시험 18개 항목을 모두 통과했다. 서기 → 주행 → 속도 제한 → 명령 끊김 시 정지 → 앉기 순서다.
  - RViz에서 서기 자세와 주행 방향이 제조사 규약과 맞는 것을 확인했다.
  - 실기에서 재현하기 위험한 상황을 단위시험 14개로 만들었다. 연결 끊김 후 재연결, 넘어짐, 서기 실패, 읽기 전용 모드 등이다.
    안전 동작을 일부러 망가뜨려 보니 시험이 매번 잡아냈다.
  - 프로그램을 종료할 때 로봇을 앉히는 처리가 일부 신호(SIGTERM)에서 오류로 끝나던 것을 고쳤다. 지금은 항상 정상 종료된다.

3. 운용 환경 구성 (완료)
  - 미니PC를 켜면 로봇 연결 프로그램이 읽기 전용으로 자동 실행된다. 이 상태에서는 로봇을 움직이는 명령을 받지 않는다.
  - 다른 PC에서 Foxglove로 로봇 상태와 3D 모델을 볼 수 있게 했다. Windows 쪽에는 ROS 설치가 필요 없다.
    기본 설정은 원격에서 조종 명령까지 보낼 수 있어서, 같은 WiFi의 누구나 로봇을 움직일 수 있는 문제가 있었다. 보기 전용으로 막았다.

4. 자율주행(Nav2) 기본 구성 (완료, 시험용)
  Zishen 때 쓰던 벤더 전용 Nav2를 대신해 표준 Nav2로 구성했다. 제어기는 Zishen과 같은 MPPI를 썼다.
  가짜 로봇으로 목표점 두 곳에 주행시켜 둘 다 도착했다 (오차 8 cm, 1 cm).
  → 아직 라이다가 없어 장애물을 못 본다. 실기 자율주행은 라이다를 붙인 뒤에 한다.

5. 로봇 자료 조사
  - 전원: 매뉴얼 그림에서 후면에 배터리 전원 출력 포트(33 V)를 찾았다. 기존에는 외부 전원 출력이 없다고 판단했는데, 이를 정정했다.
    배터리는 28.8 V, 167 Wh, 사용 시간 약 1.5시간이다 (판매처 사양 기준, 제조사 공식 사양서는 아님).
    포트 출력이 24~33.6 V로 변하므로 미니PC·라이다는 전압 변환기(DC-DC)를 거쳐야 한다.
  - 리모컨: 리모컨과 게임패드는 로봇 펌웨어가 직접 처리한다. SDK로 리모컨 입력을 읽을 수는 없고, 지금 누가 조종 중인지만 알 수 있다.
  - 로봇에서 받는 데이터: 주행에 필요한 위치·자세·관절 데이터는 단위까지 문서화돼 있다.
    IMU 가속도, 관절 토크, 배터리 전류는 단위가 문서에 없어 실기에서 확인해야 한다.
  - 제어 범위: 걷기·균형 알고리즘은 제조사 펌웨어라 수정할 수 없다. 속도·자세 명령으로 제어하는 방식(Zishen과 같음)으로 자율주행 개발에는 문제가 없다.
  - 제조사 GitHub 저장소 8개를 모두 확인했다. 공개 ROS 연동은 읽기 전용뿐이라 우리 쪽 구성이 필요하다는 판단은 그대로다.

6. 라이다 결정
  Livox Mid-360S로 정했다. Zishen에서 쓰던 Mid-360의 후속 모델이다.
  테스트 전원은 12 V, 2.5 A 이상 SMPS로 한다. 켜질 때 약 8초 동안 18 W를 쓰기 때문이다.
  로봇 배터리 포트(최대 33.6 V)는 라이다 허용 전압(27 V)을 넘는다. 로봇에 올릴 때는 반드시 12 V 변환기를 거친다.
